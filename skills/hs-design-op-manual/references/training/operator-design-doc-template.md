# 训练设计文档内容要求

正文由训练审计脚本按 facts 渲染。以下四项写入 `design` 对应字段，不能省略原有训练实现分析。

## 规格与前向前置（scope）

写算子语义、公式、输入输出、dtype、静态 shape/rank、属性、支持与拒绝规格。记录前向转换、生成 C 编译和运行的检查依据；未执行时写原因，不能只说前向注册存在。

## 反向传播设计（backward）

写可微输入和可训练参数的位置、dy 到 dx/dw/db 的公式、保留输入/输出、广播归约、布局和 alias、分支梯度累加、可选梯度、边界与不支持情形。无参数算子也要解释如何验证反向路径。

## 软件实现与复用（implementation）

分别列出 GradRule、TrainNodeCoder、NNACL fp32_grad 和 CMake 源码收集位置，说明复用、修改或新增的决定。记录训练链路、地址解析、保活与内存分配职责，禁止把数值循环写入 coder。

## 支持范围与限制（limits）

列明确认支持、明确拒绝、尚未实现的能力。权重冻结按 parser、参数选择、可选梯度地址和 kernel 判空逐层检查；不能因为旧文档描述过就标为已具备。

声明离散梯度边界的 case，要写清边界权重、并列 FP32 可训练路径和权重 dtype；
这只是按 case 受限支持，不写成通用混合精度训练。

`requires_freezing=true` 时，设计结论须覆盖实现链路、训练图、内存、权重导出和训练前后快照的可验证来源。`dW == NULL` 只写在明确要求该检查的算子里，不作为通用规则。

设计来源采用相对路径和 hash。执行结果放验证文档，不在设计结论中宣称本轮 Host/板端已通过。
