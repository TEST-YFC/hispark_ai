# 训练验证文档内容要求

正文由训练审计脚本按 facts 渲染，与设计文档分开发布。

## 测试设计（test_design）

写最小模型结构、目标节点及上游可训练参数、确定性生成器、初始化、输入和标签、训练序列、Eval 输入/标签、loss/optimizer/学习率、参考来源、逐元素容差和全部测试点。说明转换后如何确认目标未被消除；只存在于原模型不能作为已测依据。

## 本轮结果

分别写 Host 和 WS63 板端状态、未执行原因和恢复条件，不以文档同步 PASS 代替验证 PASS。默认覆盖 Predict、Eval logits/loss，以及 0/1/final 参数与非零上游更新；原始梯度没有导出时保留未逐元素比较说明。

离散梯度边界 case 另外列出 `barrier_unchanged/<name>` 和并列上游
`upstream_update/<name>`；`int32` 权重写整数精确相等结果。

## 逐用例结果

每个预期 case 保留 case_id、类型、原计划测试点、状态和原因。负向转换通过使用 PASS_EXPECTED_ERROR，不计训练数值通过。缺工具写 NOT_RUN，实际命令或数值失败写 FAIL。

## 结构与来源检查

逐项列工具包与当前源码对应、目标反向路径、训练图/内存、关闭训练时无符号泄漏。冻结任务另外列冻结参数运行时不变、上游梯度保留、optimizer/状态内存检查；不要把没有 optimizer state 写成权重不占 RAM。

## 证据索引

列模型/数据/参考生成材料、完整 summary、图与生成代码检查、构建日志、板端检测和训练记录的相对路径及 hash。结果固定在 `runs/<run_id>/`，不混入历史运行。

`requires_freezing=true` 且 Host 为 PASS 时，逐项列出实现链路、训练图、内存、导出和训练前后权重快照的证据。`dW == NULL` 只作为明确要求该检查的算子的专项结果，不写成通用验收项。
